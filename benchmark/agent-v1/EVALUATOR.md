# Evaluator procedure — protocol 1.1

The evaluator is independent of the tested agent. Keep `ground-truth.json`, assessments and previous runs out of tested-agent sessions. The tested agent's `BENCHMARK_RESULT.json` is a self-report, not independent proof.

1. Inspect the actual patch/final answer, target/build/runtime logs and that task's private ground-truth entry. Record `protocol_version: "1.1"`, `assessment_schema_version: 2`, manifest `run_id`, and `pilot: false` for a fresh run. Every `reported_tests` entry requires `name`, `status`, and boolean `verified`, even when unverified; include only fields allowed by `assessment.schema.json`. Save the assessment inside the prepared run packet beside its `RUN.json`; `check_assessment` validates the complete schema contract with a stdlib-only validator before semantic checks, and aggregation checks run identity against the frozen manifest.
1a. Record complete `environment_evidence` for every run. For A, use `applicability: "not-applicable"`, a concrete rationale, null MCP fields, and no checkout evidence. For B, MCP fields remain not-applicable/null, but checkout evidence is mandatory: set `checkout_verified: true`, record exact `knowledge_commit` and `knowledge_tree`, and point `checkout_artifact_path` to packet-local `knowledge-checkout.json`. The closed five-key `RUN.json.environment_expected` object contains `frozen_commit`, `frozen_tree`, `db_sha256`, `attestation_sha256`, and `mcp_package_version`; B must pin its exact lowercase 40-hex tree in `frozen_tree`. Its packet-local `knowledge-checkout.expected.json` sidecar must have the same commit/tree as `RUN.json`, and evaluator evidence plus the checkout artifact must match both. The artifact must contain schema version 1, the exact ordered Git commands `git rev-parse HEAD`, `git rev-parse HEAD^{tree}`, `git status --porcelain --untracked-files=all --ignored=matching`, matching HEAD/tree, and empty `status_porcelain`; ignored files are included and rejected just like other untracked/modified files. Missing, dirty (including ignored files), malformed, mismatched or external artifacts reject the Mode B assessment. For A/C, `frozen_tree` must be null. For C, all MCP fields are mandatory: compare actual server package version, MCP protocol revision, frozen commit, DB SHA-256 and attestation-file SHA-256 with canonical `RUN.json`; retain an in-packet doctor JSON artifact and set its relative path.
1b. The aggregator also hashes the packet's copied SQLite and attestation, verifies the Mode C attestation's canonical HMAC signature with the evaluator-supplied out-of-packet key, checks its payload binds the frozen protocol/commit and pinned DB, and verifies doctor JSON `structuredContent.meta.server_version` and `protocol_revision`. It also requires `structuredContent.data.index` to be an object whose `db_path`, after resolution, equals the packet's `runtime/exteracontext.sqlite`, whose `db_sha256` equals the pinned database hash, and whose `db_size_bytes` equals the signed attestation payload. Keep the doctor artifact and attestation under the packet; absolute paths, `..` escapes, symlinks resolving outside, missing files and malformed JSON fail.
1c. Important limit: doctor JSON and Mode B `knowledge-checkout.json` are operator-supplied and can be fabricated. Mode B's `RUN.json.environment_expected.frozen_tree` and sidecar record what `prepare_run.py` observed in the local checkout; the artifact is not cryptographic proof unless a trusted harness generates/collects it. Mode C's DB metadata checks strengthen packet/database binding but do not independently prove that a remote or device used that live server. These checks verify packet consistency and evaluator-inspected evidence, not device/runtime identity. Record the remaining human trust; do not describe these artifacts as machine-authenticated attestation.
2. For **each** `must_handle` ground-truth constraint, record an ordered `{constraint, passed, evidence}` verdict. `constraints_handled` is true **only** if every verdict passes; a UI callback on a worker thread fails `UI-thread return` even if other constraints pass. Empty constraint lists yield true but do not imply material completion.
3. `correct_unknown` is boolean **only** for `version-sensitive-symbol`, `donor-ayufilter`, and `unsupported-teleport`; set null for all other implementation tasks. Do not reward a closed-book baseline for merely declining implementation.
4. Independently distinguish `python_compile_success` (syntax), `target_static_success` (actual target integration/static checks), `load_success` and `runtime_success`. Unavailable checks are null, never assumed successful; compiling generic Python does not prove target integration.
5. `validate_result.py TARGET/BENCHMARK_RESULT.json` checks claimed PASS tests for command or existing local artifact. A command is reproducibility metadata, **not** proof it ran. Inspect/run the command or log yourself before marking a reported test verified; record unverified claims as `verified: false`. Verified PASS needs a reproducible command and/or an existing in-run `artifact_path`; never follow paths outside the run.
6. Set `clean_success=true` only if material completion, all constraints, target evidence boundaries, and correct-unknown where applicable succeed, with no invented target API, donor contamination, version mismatch or task-specific hard failure. Validate with `scoring.check_assessment`; do not infer runtime success from static checks.
7. Save `assessment.json` alongside the run, then aggregate only new non-pilot protocol 1.1/schema 2 records. Production aggregation requires exactly every `run_id` in the frozen 60-run manifest once; missing or duplicate IDs are rejected and listed diagnostically. The JSON output includes `clean_success_uncertainty`: per-mode estimates and paired A−B/A−C/B−C differences with 95% task-cluster bootstrap percentile intervals. The deterministic bootstrap samples the same 10 task clusters for each mode and retains both repeats per task. These descriptive intervals are conditional on the frozen task set/rubric, can be unstable with 10 clusters, and are neither significance tests nor evidence of superiority. Pilot assessments are excluded before completeness checking, so a pilot cannot fill a scheduled slot. The CLI has no partial-schedule bypass. The old v1-001 assessment is a pilot and must be rerun, not treated as an A/B/C sample. For any aggregate containing Mode C, the evaluator must supply `--attestation-key-file` pointing to the trusted operator HMAC key stored outside every run packet and outside the tested-agent workspace/session. The key must never be copied into a packet, exposed to the tested agent, or placed in command arguments/logs; pass only its file path. Mode A/B-only aggregation does not require a key. The scorer verifies the canonical payload signature and packet bindings; it does not independently establish that the human/operator assertion itself was truthful.

B needs a verified read-only checkout of Knowledge at `70f6f614227c8b02d241e7b1e72a0b6691442fd1`, exact packet-pinned tree hash, clean Git status, and a packet-local checkout artifact. A B packet prepared without `--frozen-checkout` is NOT READY and cannot be scored/aggregated. C needs a pinned, locally verified base SQLite and isolated run-local mutable SQLite, with auto-sync disabled offline. Follow `RESOURCE_SETUP.md` before manually launching a device run.
